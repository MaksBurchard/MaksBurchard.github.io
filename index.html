Predicting a player's death in League of Legends

PlaySmart esports analytics toolkit, year 3, team project, still in progress

A model that estimates, at any moment of a recorded game, the chance that the player dies within the next 5 seconds. It could help a coach find the moments worth reviewing.

My part: I wrote the death-risk modelling module and its tests. It compares a simple baseline, logistic regression, gradient boosting, a small GRU network and a time-to-die style network, using features built only from past data. Models are tuned and scored with nested leave-one-match-out validation, so no match appears in both training and testing. The tuned logistic regression scored best, narrowly ahead of the neural networks.

The project is still running, so these results are from halfway through the block and may change. The sample is small (27 sessions, 16 matches, 1,638 deaths), and the model mostly spots a health collapse already under way. The team used an AI coding assistant on this project and says so in the project README; I can explain every module I wrote.

Python, pandas, NumPy, scikit-learn, pytest

Robot arm control: PID against reinforcement learning

Year 2, block B, individual

The task was to move the pipette tip of a simulated Opentrons OT-2 liquid-handling robot to any target in its workspace.

I tuned a PID controller and, separately, built a custom Gymnasium environment and trained a PPO agent with a reward that combines a time penalty, a distance penalty and a success bonus. I also connected the controller to a computer-vision pipeline that finds root tips.

The PID controller won for this task. The RL agent reached the 5 mm target every time but never got below 1 mm, because I trained it to stop at 5 mm.

Python, PyBullet, Stable-Baselines3, Gymnasium, TensorBoard

Plant root phenotyping as a deployed ML system

Year 2, block D, team of four

A full stack that detects and separates plant roots in images, collects user feedback, retrains the models and redeploys them. It uses an RT-DETR detector and SegFormer models, behind a FastAPI backend and a Streamlit frontend, with Airflow, MLflow, Docker and a CI/CD pipeline that gates merges on 85% test coverage.

My part: I added the MLflow experiment tracking to training, evaluation and the retraining loop. I also wrote the cost comparison of cloud against on-premises deployment, and the demo day documentation and poster.

Earlier, in block B, I individually built a computer-vision pipeline that finds root tips in plant images and guides a robot (see the robot project above). The team did not use that part here, but it means I know the root-imaging side as well.

Python, MLflow, Docker, FastAPI, Airflow, GitHub Actions

Emotion in TV shows from speech

Year 2, block A, team of three

A pipeline that turns a video into text and then into labelled emotions, as a cheaper local alternative to large language models.

My part: I built and iterated on Naive Bayes and BERT-style classifiers, wrote the baseline, and worked on error analysis and explainability, using gradient times input, layer-wise relevance propagation and a token-removal test on a RoBERTa model.

Python, scikit-learn, transformers, AssemblyAI, Whisper

Predicting arousal at historic forts

Year 2, two-week challenge at the end of block B, individual

The goal was to predict a visitor's skin-conductance response (phasic_z) from location and time features while they visited forts in the Netherlands and Belgium.

My part: everything, from feature engineering to the report. I built many features, kept the most important ones and compared a model trained on a subset against one trained on all the data.

The subset model beat the full-data model. My hypothesis is that the subsets were dominated by single forts, so a model per fort may work better. I did not have time to test it, and the report says so.

Python, pandas, scikit-learn, geospatial features
